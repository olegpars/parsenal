# dr-fanout — разослать deep research по 4 браузерным моделям (Chrome MCP)

Прокликиваешь deep-research в **ChatGPT + Gemini + Claude + Grok** через Chrome MCP (`mcp__Claude_in_Chrome__*`). Вход: **один промт** (4 прогона = триангуляция) или **N промтов** (N×4). Это браузерные подписки пользователя, НЕ API-токены. Если пользователь явно просит «в трёх моделях» — режим без Grok тоже валиден.

## Подготовка
- `list_connected_browsers` → `tabs_context_mcp{createIfEmpty:true}`. Один таб на модель (логин уже в Chrome). Research идёт **server-side** — навигация табом на новый чат НЕ останавливает запущенный прогон, поэтому несколько промтов в одной модели = тот же таб через «новый чат».
- **Gemini account guard — до касания composer:** перед вводом проверь по видимому имени/email в меню профиля Gemini, что активен тот Google-аккаунт, которым ты собираешься пользоваться для deep research. URL вида `/u/N/app` аккаунт не подтверждает. Под чужим или неопознанным аккаунтом не включай Deep Research, не вставляй промт, не отправляй его, не создавай план и не начинай исследование — сначала переключись на нужный аккаунт. Если нужного аккаунта в браузере нет или личность профиля неясна — пропусти Gemini, продолжи остальные модели и сообщи: `Gemini skipped: wrong/unknown account`.
- Промты готовь заранее, на английском (шире источники). **Чувствительные данные во внешние модели не вставлять.**

## Вставка длинного промта (критично)
Никогда не печатай многострочный промт через `computer` `type` — `\n` = Enter = ранняя отправка. Фокус на composer + `javascript_tool`:
`el.focus(); document.execCommand('insertText', false, PROMPT)` — переносы строк не сабмитят. `el` = `div.ProseMirror[contenteditable]` / `div.ql-editor` / `[contenteditable=true]`.

## Поток по моделям
- **ChatGPT** — `+` → **Deep research** → вставить → send → появится план с авто-countdown → клик **Start** (или само стартует ~60с).
- **Gemini** — сначала пройди **Gemini account guard** выше и явно подтверди, что активный профиль — тот, которым ты собираешься пользоваться; только затем `+` → **Deep Research** → вставить → send → сгенерит план (~15-25с) → клик **«Начать исследование»**.
- **Claude** — `+` → **Research** (свериться: синяя лупа у `+` / галка в меню) → вставить → **Enter** → диалог **«Enable connectors»** → **«Disable all tools» → Confirm** (приватность: не давать Gmail/Calendar/Drive; web search остаётся).
- **Grok** — `grok.com` (нужна подписка с deep research). **Отдельной кнопки DeepSearch НЕТ** — старый DeepSearch слит в режимы модели: дропдаун справа в composer (подпись = текущий режим, напр. «Heavy») → выбрать **Heavy** («Team of Experts» · Grok 4.5 — глубже и дольше, тратит Heavy-квоту; **дефолт для fan-out**) или **Expert** («Thinks hard» · Grok 4.5 — быстрее и экономнее; только если пользователь явно просит сберечь Heavy-квоту). Composer = `div.tiptap.ProseMirror[contenteditable=true]`, вставка тем же `insertText` (переносы строк НЕ сабмитят — проверено). Send = круглая кнопка-стрелка справа. В «+»-меню только файлы/Skills/Connectors — режим ресёрча там не ищи. Чат получает URL `grok.com/c/<uuid>`; следующий промт — «New Chat» в сайдбаре.

**Не путать:** поиск по X (Twitter) идёт отдельным проходом через headless Grok CLI, а не через браузерный Grok выше — здесь Grok участвует только как одна из 4 моделей фан-аута deep research.

## Гочи (проверено боем)
- **Проверяй запуск через DOM, не скриншоты** — скриншоты таймаутят, когда рендерер занят. Маркеры идущего прогона: «Searching for sources» / «Researching» / «and counting» / появившаяся кнопка плана.
- **Меню ре-рендерятся** (короткое→длинное, ~1-2с) — подожди и кликай по `find` / `read_page` ref'ам, не по фиксированным координатам. Первый клик по `+` после навигации часто даёт tooltip, не меню — кликни ещё раз.
- **Claude**: недельный лимит реален и НЕ любит >1 concurrent deep research. Упавший / «Stopped» / «Something went wrong» прогон **лечится НОВЫМ чатом, не Retry**. Следующий промт запускай после того, как предыдущий реально пошёл.
- **Grok**: маркеры идущего прогона в DOM — «Worked for Ns» / «Ran N searches» / «Searching for…»; готовый ответ заканчивается блоком «N sources». Продолжается ли прогон server-side при уходе таба с чата — НЕ проверено (для других трёх проверено, что да); до проверки следующий Grok-промт запускай после завершения предыдущего либо в отдельном табе.
- Каждый прогон ~5-30 мин; ChatGPT обычно быстрее всех. Полный DR-прогон Grok (Expert на большом промте) на 2026-07-27 живьём не гонялся — проверен короткий Expert-запрос с web-поиском (канал работает end-to-end).

## Сбор отчётов — сохранять ФАЙЛАМИ, не ссылками (критично)
Ссылка на чат бесполезна для другой сессии (нет доступа к авторизованному вебу). **Всегда сохраняй ТЕКСТ отчёта в файл** в репо проекта, например `operations/<тема>/reports/<prompt>-<model>-report.md`. Имя файла никогда не равно `claude.md` или `agents.md`: Windows нечувствительна к регистру, и такой файл автоподхватится агентами как CLAUDE.md/AGENTS.md-инструкции. Извлечение по платформам (проверено боем):
- **Claude** ✅ — отчёт = artifact. Кликни карточку артефакта (клик по координате надёжнее ref) → текст появляется в DOM → возьми самый большой блок (`div.flex-1.min-h-0.overflow-y-auto`) → сохрани **blob-download** (`new Blob([text])` + `a.download='X-claude-report.md'` + click, потом `Move-Item` из Downloads). Текст НЕ идёт через контекст, точно.
- **ChatGPT** ❌ — отчёт в cross-origin sandbox iframe (`*.web-sandbox.oaiusercontent.com`): DOM / clipboard / iframe-src закрыты. Только кнопка **Download** самого отчёта (PDF) ИЛИ человек копипастит.
- **Gemini** ❌ — отчёт в immersive-вьювере, текста в DOM нет (только CSS). Только **«Создать» → Export to Docs** (затем читать через Drive MCP) ИЛИ человек копипастит.
- **Grok** ✅ — ответ лежит **прямо в DOM** (`<main>`): `get_page_text` забирает целиком, blob-download работает так же, как у Claude. Никаких sandbox-iframe. Проверено 2026-07-27.

**Вывод:** blob-метод надёжен для Claude и Grok. **НЕ оставлять в хендоффе голые URL** — другая сессия их не откроет. Итог — таблица промт×модель со статусом; мёртвые чаты помечай «игнор».

**Подтверждено боем 2026-06-17:** download/copy у ChatGPT и Gemini требуют **trusted user-gesture** — синтетические клики Claude_in_Chrome их НЕ запускают (меню Download в sandbox-iframe не открывается; «Copy response» не пишет clipboard без user-activation; Gemini-текст не в DOM). Т.е. авто-выкачка готовых отчётов оттуда **невозможна** — только руками. Альтернатива на пробу: **Codex browser plugin + `$chrome` скилл для Codex** (своя браузерная автоматизация, качает там, где Claude_in_Chrome не может).

## Чего НЕ делать
Не вставлять чувствительные данные во внешние модели. **Не запускать и даже не подготавливать Gemini Deep Research под чужим или неопознанным Google-аккаунтом — если нужного подтверждённого аккаунта нет, Gemini пропускается.** Не оставлять Claude-коннекторы включёнными. Не печатать промт raw `type`-ом. Не дёргать Retry на упавшем Claude-прогоне (только новый чат). Не искать в Grok кнопку «DeepSearch» (её нет — режим = дропдаун модели) и не спускаться на Expert самовольно (дефолт — Heavy; Expert только по явной просьбе пользователя сэкономить квоту). Не путать с локальным `deep-research` харнессом и `kopatel`.
